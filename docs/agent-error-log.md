# Recurring Agent Error Log

Each entry has: date, task in progress, the error, the cause, and the action taken or needed. Newest entry on top. An error that has been automated is marked "Automated as: ...". The end-of-module retro (`docs/process/lifecycle.md` § Recurring Errors and End-of-Module Retro) adds entries here; with several team members, record every member's errors and let the retro merge them.

The goal: within 2-3 weeks, each recurring error becomes a lint rule, an architecture test, a regression test or a generator, not just another line in a prompt.

## Pending retro

Process improvement ideas that arise mid-module go here, one per line with the date. The end-of-module retro handles and then removes them.
